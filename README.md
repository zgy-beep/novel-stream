## 核心特性

- **问候语延迟入书**：新开聊天查看角色卡或调试预设时不会生成任何废弃章节；只有当你发出第一句消息、真正开启剧情时，角色问候语才会作为第 1 章入书，从开头就完整，绝不漏章。
- **无状态实时派生**：插件不维护任何跨消息的持久状态，章节永远从当前聊天记录实时重新计算。点击重新生成 (Regenerate) 或划动分支 (Swipe) 后，整书自动按最新记录派生，绝不残留废弃废案。
- **阅读器自动识别目录**：默认采用「第 X 章 · 角色名 (原楼层: Y)」格式，导入微信读书、ReadEra、掌阅、多看等主流阅读器时自动生成可点击的树状目录，同时标明酒馆原始楼层，回溯查验极为直观。
- **原生 UTF-8 BOM 编码**：导出文件首章自动写入 UTF-8 BOM 标识与《书名》扉页，彻底杜绝老旧车载系统、老版 Windows 记事本、电子墨水屏出现乱码。
- **多角色群聊自动聚合**：智能识别群聊环境，将群内所有角色的回复统一编排进同一本群小说（`[群聊] 群名称 - 对话名.txt`），剧情连贯不撕裂。
- **四阶段深度清洗引擎**：
  - 全自动剥离各类思考模型的思维链（`<think>`、`<cot>` 及各类反代无头闭合标签，通用支持 DeepSeek、Claude 等）；
  - 过滤 HTML 注释与 `![图片](url)` 标记，回归纸质纯文字阅读体验；
  - 白名单模式：预设将正文写在 `<story>` 等标签内时，只提取该标签内容，自动丢弃外部所有杂乱元数据；
  - 黑名单模式：深度剥离 `<status>`、`<memory>`、`<ooc>`、`<variables>` 等信息卡，且带 sig 校验的清洗缓存，长聊天不重复计算。
- **中文小说规范排版**：段落首行自动空两格，扉页、章题、正文层次分明。
- **主角对白可选融入**：一键将你的发言也作为对话写入小说；关闭则只收录 AI 回复。
- **魔法棒菜单入口**：点开聊天输入框左下角的酒馆原生魔法棒，菜单里的「小说连载阅读」带连载状态副标（连载中 / 已关闭），点一下直接弹出设置面板，入口就在手边。
- **三标签设置面板**：所有配置集中在「连载 / 过滤 / 文件」三个标签页——桌面端标签行在面板标题下方，手机端标签栏落到面板底部（拇指够得到）。每个设置分组都是一枚可折叠分组条，右侧直接显示当前值，默认全部收起；展开过哪些块会被记住，下次打开还是你上次的排布。面板支持 Esc / 关闭钮 / 点遮罩关闭，焦点在面板内循环、关闭后归还触发元素。
- **纯前端一键导出**：不配置任何服务端、不碰终端，点击「导出整本 TXT」即由浏览器本地生成并下载整本小说；导出后面板状态行显示文件名、章节数与时间，折叠组摘要同步更新，并弹出一次性成功提示。当前没有可导出章节时会弹出警告且不产生下载。

## 快速上手

1. 打开 SillyTavern，点击顶部栏的**扩展管理图标（积木 / 方块图标）**。
2. 点击 **Install Extension（安装扩展）**，在输入框中粘贴仓库地址：
   ```text
   https://github.com/zgy-beep/ST-auto-save-to-txt
   ```
3. 点击保存安装，完成后**刷新浏览器页面**。

此时输入框左下角的魔法棒菜单里会出现**「小说连载阅读」**，点一下即可打开设置面板。直接开始对话，小说即自动编排；想拿文件时，切到「文件」页点**导出整本 TXT** 即可。

> 本插件为纯前端扩展：全部计算与导出都发生在你的浏览器里，没有服务端插件、没有网络请求、没有落盘路径需要配置。

## 设置手册

点击魔法棒菜单中的「小说连载阅读」打开面板。三个标签页分别负责连载、过滤与文件，任何标签下都可以看到顶部的导出操作与底部的双按钮。

### 连载页：章节格式与主角对白

- **开启小说自动连载**：连载总开关。关闭后 AI 回复不再入书，已编排的内容仍可随时导出；魔法棒副标会同步变为「已关闭」。
- **章节格式**（折叠组，右侧显示当前风格）：
  - 章节目录风格，四选一：
    - `第 X 章 · 角色名 (原楼层: Y)`（推荐）：各大阅读器完美识别为目录，同时标明酒馆楼层，回溯查验极为方便；
    - `第 X 节 · 角色名`：纯净目录，不包含楼层信息；
    - `优雅分割线 (* * *)`：散文体，章节之间仅用星号隔开；
    - `纯净戏剧体 (【角色名】)`：剧本体，适合角色对话密集的场景。
  - 段落首行缩进（空两格）：中文小说规范排版，可随时关闭。
- **主角对白**（折叠组）：开启后，你在酒馆里的发言也会作为章节写入；关闭则只收录 AI 回复。
- **内置智能机制**（折叠组，只读说明）：延迟入书、末尾替换、章节计数三条机制的当前工作方式。

### 过滤页：白名单与黑名单

玩酒馆最头疼的就是预设带有的 `<status>` 状态栏、`<think>` 思考过程、`<ooc>` 闲聊杂项。本插件提供双重过滤机制，思考链由引擎自动识别，无需手动填写。

```text
[原始 AI 回复]
      │
      ▼
【白名单匹配】─(未设置)────────────> [保留全部内容]
      │
      └──────(设置了标签，如 story)─> [仅提取 <story>...</story> 内部内容]
                                              │
                                              ▼
                                      【黑名单深度剔除】
                                      (剔除 status, memory, ooc ...)
                                              │
                                              ▼
                                      [纯净优雅的小说正文]
```

- **正文白名单**（折叠组，右侧显示当前设置）：
  - 如果你的预设把正文包裹在固定标签里（例如 `<story>正文</story>`），在此填入 `story`；
  - 留空代表整篇全保留。若不确定预设是否有专门的正文标签，**务必留空**。
- **排除黑名单**（折叠组，右侧显示标签个数）：
  - 填入要剔除的标签，用半角逗号隔开，默认内置：`status,memory,details,variables,analysis,ooc,note,draft,system,log`；
  - 这类标签及其包含的全部子内容会被完整剪除；
  - 点击「恢复默认」一键还原默认黑名单。

### 文件页：命名规则与一键导出

- **文件命名规则**（折叠组，右侧显示当前规则）：
  - `角色名 - 对话名`（推荐）：每个新开的聊天都会生成独立的文件（如 `艾莉丝 - 远征探索.txt`），平行世界或新开局绝不串台、绝不相互覆盖；
  - `仅角色名`：该角色的所有对话都会编排进同一本小说（如 `艾莉丝.txt`）。
- **导出整本 TXT**（折叠组，右侧显示最近导出摘要）：
  - 纯前端本地下载，即点即存，文件带 UTF-8 BOM 与《书名》扉页；
  - 状态行显示最近一次导出的文件名、章节数与时间（如「今天 21:36 · 第 12 章」），成功后弹出一次性提示；
  - 当前聊天没有可导出的有效章节时（例如过滤规则过严），会弹出警告且不产生下载——请先开始对话，或回到「过滤」页检查白 / 黑名单。

## 手机阅读器导入指南

导出的 TXT 小说天然针对各大主流阅读软件深度调优：

```text
《艾莉丝 - 远征探索》

第 1 章 · 艾莉丝 (原楼层: 1)

　　夜幕低垂，微风拂过静谧的街角。艾莉丝合拢被风吹乱的斗篷，蓝色的眼眸在月光下泛着淡淡的光泽。
　　“你终于来了。”她轻声说道，嘴角扬起一抹似有若无的微笑。


第 2 章 · 艾莉丝 (原楼层: 3)

　　她转过身，示意你跟上她的脚步。远处的钟楼适时敲响了午夜的钟声……
```

主流阅读器导入方式：

1. **微信读书**：打开 App，点击【书架】右上角【+】，选择【从本地导入】，选中导出的 `.txt` 文件。微信读书将自动识别「第 X 章」并生成层级目录，支持进度云同步与 AI 听书。
2. **ReadEra（安卓）**：将 TXT 放入手机存储目录或网盘同步文件夹，ReadEra 会自动扫描并完美展现章节目录树，且无任何广告。
3. **掌阅 / 多看阅读 / 苹果图书**：原生兼容 UTF-8 BOM 编码，打开即阅，告别文字乱码与段落挤压。

## 常见问题 (FAQ)

**Q1：为什么新开聊天角色发了第一句话，却还没有任何章节？**

这是特意设计的「延迟入书机制」。很多玩家会频繁导入角色卡、调试打招呼设定或看卡面，如果打开聊天窗口的第一秒就入书，目录里会堆满只写了一句打招呼的废弃章节。因此：**当你发出第一句消息正式开始对话时，角色的问候语才会作为第 1 章入书**，保证小说从最开端就完整无缺，同时绝不产生空卡垃圾章节。

**Q2：重新生成 (Regenerate) 或划动多条回复 (Swipe) 后，旧的废弃剧情会留在小说里吗？**

不会。章节无状态、每轮从当前聊天记录实时重新派生，重 roll 或划动后整书自动按最新记录编排，txt 与酒馆当前画面保持完全同步。

**Q3：提示「当前聊天没有可入书的有效正文」怎么办？**

说明过滤规则可能过于严格（例如白名单填了 AI 根本没用过的标签名，导致过滤后剩余 0 字）。回到「过滤」页将白名单**完全留空**（留空 = 保留全部正文），或酌情删减黑名单标签。

**Q4：我想把自己（主角 / 玩家）的互动对话也写进小说，可以吗？**

可以。在「连载」页展开「主角对白」分组，开启「将主角（你的发言）融入小说」即可；你的发言将作为对话融入章节。关闭则只收录 AI 回复。

**Q5：微信读书导入后，为什么有些章节目录出不来？**

请将章节目录风格保持为默认的「第 X 章 · 角色名 (原楼层: Y)」。这种格式完全符合国内主流阅读器的目录识别算法；同时导出的 TXT 带有 UTF-8 BOM 标识，导入后即可自动解析出目录，绝无乱码。

**Q6：群聊里多个角色的回复会分裂成多本书吗？**

不会。群聊环境下所有角色的回复会统一编排进同一本群小说，文件名为 `[群聊] 群名称 - 对话名.txt`，剧情连贯不撕裂。

## 项目结构

```text
ST-auto-save-to-txt/
├── index.js                  # 前端核心扩展代码（清洗引擎 / 章节派生 / NVUI 面板 / 导出逻辑）
├── style.css                 # 前端样式表（小说面板节奏规则；Kit CSS 由 index.js 运行时注入）
├── manifest.json             # SillyTavern 官方扩展清单定义
├── README.md                 # 项目使用与排障指南
├── .gitignore                # Git 忽略配置
├── ui-kit/                   # NVUI Kit v2.2.0（CDN 在线优先时的本地离线兜底 vendor）

    ├── test-version-compare.js   # 语义版本比较回归测试

    ├── test-universal-tags.js    # 通用标签清洗引擎测试（引擎抽自真实源码）
    ├── test-chapter-map.js       # 章节派生与楼层映射测试（抽自真实源码）
    ├── test-export-build.js      # 导出编排测试（抽自真实源码）
    └── test-mvp-panel.js         # 面板端到端测试（playwright 页内装配真实源码）
```
